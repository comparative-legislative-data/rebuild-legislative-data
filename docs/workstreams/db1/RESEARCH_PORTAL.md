# DB1 Research Portal

**Status:** Planned — blocked until Backend Assurance is accepted.

## Product purpose

The Research Portal is not a database administration interface. It is a modern
research tool that lets people discover, understand, inspect, retrieve and cite
the source-preserving material DB1 has demonstrably retained.

It has two equal responsibilities:

1. present DB1 as a dated mirror of named Scottish Parliament API responses;
2. make that mirrored material materially easier to use than the live API,
   without disguising which features are CLD-generated.

## Non-negotiable experience

The portal is organised around research tasks, not captures, manifests,
projection names, timers or database tables. A researcher must be able to:

- find a source through subjects, search and clear endpoint descriptions;
- see coverage, capture/reconciliation status and each source exception;
- distinguish the dated mirror from the live Scottish Parliament API;
- access an individual original retained response;
- retrieve an all-years original-source archive when that capability exists;
- use declared CLD-generated formats such as JSONL, CSV and Parquet only when
  their conversion contract has been published;
- inspect records and fields where the backend says this is safe and useful;
- obtain citations, provenance and framework-specific code examples; and
- learn what is unavailable without encountering developer terminology.

## Product boundary

The portal receives a Backend Assurance capability contract. It does not infer
availability from route names, recreate coverage logic, or display an internal
fallback as a user feature. Every visible action must have a real, tested
result.

| Layer | Portal language | Required disclosure |
| --- | --- | --- |
| Original retained response | “Original JSON held by the Database mirror” | Source URL, capture date, checksum and source condition. |
| All-years archive | “Download all retained original responses” | Archive contents, included/excluded years and manifest. |
| CLD access format | “CSV/JSONL/Parquet generated by CLD” | Format/conversion version, schema and relationship to original JSON. |
| Record preview | “Browse retained records” | Convenience view; raw response remains primary. |
| Live source | “Open live Scottish Parliament API” | External; current response may differ from DB1 capture. |

## Delivery sequence

1. Accept Backend Assurance outputs.
2. Approve this product contract and a download-format contract.
3. Build a static, high-fidelity portal prototype without backend coupling.
4. Owner tests the researcher journey before integration.
5. Implement only capabilities proved by the backend contract.
6. Run task-based accessibility and acceptance tests before release.

## Acceptance tasks

1. Find Committee Official Reports and identify coverage and the 2006 upstream
   availability exception.
2. Download a named retained original response and verify provenance.
3. Obtain a genuine all-years archive and identify included/excluded years.
4. Distinguish a CLD-generated format from original source JSON.
5. Locate fields, citation and a code example without encountering DB1 internal
   implementation terms.

No portal release is complete merely because the application builds or a unit
test passes.
